# bra-B TypeScript バックエンド

本ディレクトリには、bra-B アプリケーションの TypeScript（Hono）で実装されたバックエンドが含まれています。ドメイン駆動設計（DDD）とレイヤードアーキテクチャを採用し、責務の分離と保守性の高いコードベースを実現しています。

## アーキテクチャ概要

bra-B TypeScript バックエンドは以下の設計原則に基づいています：

- **ドメイン駆動設計（DDD）**: ビジネスドメインを中心とした設計
- **レイヤードアーキテクチャ**: 関心事の分離によるメンテナンス性の向上
- **依存関係の方向性**: 外側から内側への依存（内側のレイヤーは外側のレイヤーに依存しない）
- **明確なインターフェース**: リポジトリパターンによるデータアクセス層の抽象化

## 技術スタック

- **サーバーフレームワーク**: [Hono](https://hono.dev/) - 軽量かつ高速な Web フレームワーク
- **ORM**: [Prisma](https://www.prisma.io/) - TypeSafe なデータベースアクセス
- **データベース**: PostgreSQL
- **バリデーション**: [Zod](https://zod.dev/) - スキーマ検証と型安全性の確保
- **認証**: JWT（JSON Web Token）

## レイヤー構成

### 1. ドメイン層 (`domain/`)

ビジネスロジックとエンティティを含む中心的な層です。

- `models/`: ドメインモデル（エンティティ）と型定義
- `repositories/`: データアクセスのためのインターフェース定義

### 2. リポジトリ層 (`repositories/`)

データアクセスロジックを実装します。ドメイン層で定義されたインターフェースに依存します。

- Prisma を使用したデータベースアクセス
- ドメインモデルとデータベースモデルの変換

### 3. サービス層 (`services/`)

ユースケースとビジネスフローを実装します。

- ドメインモデルとリポジトリを使用
- トランザクション境界の制御
- ビジネスルールの適用

### 4. プレゼンテーション層 (`routes/`)

API エンドポイントとリクエスト/レスポンスの処理を担当します。

- Hono ルーターの定義
- リクエストのバリデーション（Zod）
- レスポンスの整形

## 依存関係の方向

依存関係は常に外側から内側に向かいます：

```
routes → services → domain ← repositories
```

## セットアップと実行方法

### 前提条件

- Node.js 18.0.0 以上
- npm または yarn
- PostgreSQL データベース

### 初期設定

```bash
# 依存パッケージのインストール
npm install

# .env ファイルの作成
cp .env.example .env
# .env ファイルを編集してデータベース接続情報などを設定

# Prisma クライアントの生成
npm run prisma:generate

# データベースマイグレーション
npm run prisma:migrate
```

### 開発サーバーの起動

```bash
# 開発モードで起動（ホットリロード）
npm run dev
```

### ビルドと本番実行

```bash
# TypeScript のビルド
npm run build

# 本番モードで起動
npm run start
```

## 開発ガイドライン

### ドメインモデルの追加

1. `domain/models/` に新しいモデルを定義
2. `domain/repositories/` に対応するリポジトリインターフェースを定義
3. `repositories/` にリポジトリ実装を追加
4. 必要に応じて `services/` にサービスを追加

### API エンドポイントの追加

1. `routes/` に新しいルートファイルを作成
2. 必要に応じて Zod スキーマを定義
3. `index.ts` で新しいルートを登録

### リポジトリの実装

- ドメインモデルとデータベースモデルの変換に注意
- 全てのビジネスロジックはドメイン層かサービス層に配置
- リポジトリはデータアクセスのみを担当

### サービスの実装

- 複数のリポジトリを組み合わせて複雑なユースケースを実装
- トランザクション境界を明確に定義
- 副作用は最小限に抑え、純粋関数を優先

## トラブルシューティング

### Prisma エラー

Prisma スキーマとデータベースの同期が取れていない場合：

```bash
# マイグレーションの再実行
npm run prisma:migrate

# Prisma クライアントの再生成
npm run prisma:generate
```

### TypeScript のビルドエラー

型エラーが発生した場合：

```bash
# 型チェックのみ実行
npx tsc --noEmit
```
