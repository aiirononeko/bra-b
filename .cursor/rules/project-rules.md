# Bra-B プロジェクトルール

## プロジェクト概要
Bra-Bは「お店」ではなく「バリスタ」に焦点を当てたバリスタ評価サービスです。ユーザーがバリスタ起点でコーヒーを飲みに行くようなカフェ体験を提供します。

## 技術スタック
- フレームワーク: Next.js 15.2.4 (App Router)
- バックエンド: API Routes (Next.js)
- フロントエンド: React 19
- データベース: Supabase (PostgreSQL)
- 認証: Supabase Auth
- ストレージ: Supabase Storage
- サーバーレス関数: Supabase Edge Functions (Deno)
- デプロイ: Vercel
- スタイリング: Tailwind CSS 4.x
- パッケージマネージャー: pnpm (npmは使わない)

## プロジェクト構造

### ディレクトリ構造
- `app/`: Next.js App Routerのメインディレクトリ
  - `actions/`: サーバーアクション
  - `admin/`: 管理者ページ
  - `auth/`: 認証関連ページ
  - `barista/`: バリスタ関連ページ
  - `components/`: 共通コンポーネント
  - `evaluate/`: 評価関連ページ
  - `lib/`: ユーティリティライブラリ
  - `repositories/`: データアクセス層
  - `utils/`: ユーティリティ関数
- `supabase/`: Supabase関連ファイル
  - `functions/`: Edge Functions
- `public/`: 静的ファイル

### データモデル
- Profile: ユーザープロファイル（ユーザー、バリスタ、匿名ユーザー）
- Evaluation: バリスタ評価
- EvaluationDetail: 評価詳細
- EvaluationItem: 評価項目
- BaristaCategory: バリスタカテゴリ（4種類）
- Tip: チップ情報
- Favorite: お気に入り情報

## コーディング規約

### 共通規約
1. TypeScriptの型を適切に使用する
2. 関数はエクスポート前に適切な型定義を行う
3. コンポーネントは明確な単一責任を持つ小さい単位で作成する
4. コメントは必要に応じて追加する（特に複雑なロジック）

### Next.jsコンポーネント規約
1. サーバーコンポーネントを優先的に使用する
2. クライアントコンポーネントは`'use client'`ディレクティブを先頭に明示する
3. ページコンポーネントはページディレクトリに`page.tsx`として配置する
4. レイアウトコンポーネントは`layout.tsx`として配置する

### API規約
1. APIルートはNext.js App Routerの規約に従う
2. データベースアクセスは`repositories`ディレクトリの関数を使用する
3. サーバーアクションは`actions`ディレクトリに定義する
4. エラーハンドリングは適切に行い、ユーザーフレンドリーなエラーメッセージを返す

### 認証・権限管理規約
1. 認証にはSupabase Authを使用する
2. 匿名ユーザーと認証ユーザーの権限を明確に区別する
3. バリスタ機能はバリスタ権限を持つユーザーのみアクセス可能

### 評価システム規約
1. 評価は4つのカテゴリに基づき行われる：
   - フレンドリー
   - 美味しい一杯を届ける
   - 洗練されたサービス
   - エンターテイナー
2. 評価項目はシンプルに選択式のみとし、自由記述はチップ送信時のみ可能
3. バリスタカテゴリはユーザー評価に基づき自動計算される

### ストレージ規約
1. ユーザー画像等はSupabase Storageに保存する
2. 適切なアクセス制御を設定し、不正アクセスを防止する

## 開発ワークフロー
1. 依存関係の追加はPnPMを使用する
2. 開発はfeatureブランチで行い、プルリクエスト経由でマージする
3. コード品質はBiomeを使用して維持する

## デプロイメント
1. Vercelを使用してデプロイを行う
2. Supabase Edge Functionsは専用コマンドでデプロイする

## Next.js 15の注意点
- Next.js 15からcookies()などのリクエスト依存APIが非同期から同期に変更されました
- 現在使用中の@supabase/ssrバージョン0.6.1はまだPromiseを返すcookies()を期待しているため、互換性維持のためawaitキーワードを保持する必要があります
- Supabaseとの認証関連処理では特に注意が必要です

## パッケージ管理
- 依存関係の追加・更新は必ずpnpmコマンドを使用する
- `pnpm add <パッケージ名>` - パッケージのインストール
- `pnpm update <パッケージ名>` - パッケージの更新
- `pnpm remove <パッケージ名>` - パッケージの削除
- npmやyarnは使用しないこと（pnpmとの依存関係解決に差異があるため）
