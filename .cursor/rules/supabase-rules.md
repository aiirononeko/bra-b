# Supabase関連ルール

## データベース設計

### Profileテーブル
- ユーザー、バリスタ、匿名ユーザーの情報を管理
- `type`フィールドで種別を区分（"user", "barista", "anonymous"）
- 匿名ユーザーは`anonymous_id`でCookieと紐付け
- バリスタは店舗名などの追加情報を持つ

### 評価システム
- `Evaluation`テーブル: 評価の基本情報
- `EvaluationDetail`テーブル: 評価項目の選択情報
- `EvaluationItem`テーブル: 評価項目マスタ
- `BaristaCategory`テーブル: バリスタのカテゴリ計算結果

### お気に入り・チップ機能
- `Favorite`テーブル: ユーザーのお気に入りバリスタ情報
- `Tip`テーブル: バリスタへのチップ情報（Stripe決済連携）

## Edge Functions

### update-barista-category
- バリスタの評価カテゴリを自動計算する関数
- 評価データに基づいて4つのカテゴリスコアを算出
- 最も高いスコアのカテゴリがメインカテゴリとなる
- 信頼度スコア（confidence_score）も計算

## 認証システム

### 認証方式
- マジックリンク認証
- Google認証

### 匿名ユーザーシステム
- 初回アクセス時に匿名IDを生成（Cookie保存）
- 匿名ユーザー用のプロファイルを作成
- 認証後は匿名ユーザーデータを認証ユーザーに移行

### 権限設計
- 匿名ユーザー: バリスタ閲覧、お気に入り登録のみ
- 認証ユーザー: 評価、チップ送信、プロフィール編集など
- バリスタユーザー: 自身のプロフィール管理、評価・チップ受け取り

## ストレージ

### 画像ストレージ
- プロフィール画像はSupabase Storageに保存
- 適切なバケット設計とアクセス制御を実装

## 開発・デプロイ

### Edge Function開発
1. `pnpm supabase functions serve`でローカル開発
2. `pnpm supabase functions deploy`でデプロイ

### マイグレーション管理
- `migrations`ディレクトリでスキーマ変更を管理
- バージョン管理されたマイグレーションファイルを使用

### シード管理
- `seed.sql`でテストデータを提供
- 開発環境用の初期データセットを定義
